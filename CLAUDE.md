## Project Overview

**n8n-installer** is a Docker Compose-based installer for deploying a comprehensive self-hosted AI workflow automation environment. The project bundles n8n (workflow automation), Flowise (AI agent builder), and 20+ optional services (Supabase, Qdrant, Langfuse, Open WebUI, Ollama, Grafana, etc.) behind Caddy reverse proxy with automated HTTPS.

## Core Architecture

### Installation Flow

The main installer (`scripts/install.sh`) orchestrates 7 sequential steps:

1. **01_system_preparation.sh** - Updates system, configures UFW firewall, enables Fail2Ban
2. **02_install_docker.sh** - Installs Docker and Docker Compose
3. **03_generate_secrets.sh** - Generates `.env` from `.env.example`, creates secrets/passwords/hashes
4. **04_wizard.sh** - Interactive whiptail-based service selection wizard
5. **05_configure_services.sh** - Configures selected services (Supabase setup, etc.)
6. **06_run_services.sh** - Starts services via `docker compose up -d`
7. **07_final_report.sh** - Displays URLs, credentials, and access information

### Service Profile System

Services are activated via Docker Compose profiles (defined in `COMPOSE_PROFILES` env var). Core services (Caddy, Postgres, Redis) run without profiles. Optional services require profile activation:

- `n8n` - Includes n8n main app, n8n-import, and n8n-worker (scalable via `N8N_WORKER_COUNT`)
- `flowise`, `open-webui`, `langfuse`, `qdrant`, `supabase`, `monitoring`, etc.
- Special profiles: `cpu`, `gpu-nvidia`, `gpu-amd` (for Ollama hardware selection)

### n8n Queue Mode Architecture

n8n runs in queue mode by default:
- **n8n** container: Main web UI and API
- **n8n-worker** containers: Process workflow executions (configurable replicas via `N8N_WORKER_COUNT`)
- **n8n-import** container: One-shot service to import ~300 community workflows (if `RUN_N8N_IMPORT=true`)
- **Redis (Valkey)**: Task queue backend
- **Postgres**: Data persistence

### Caddy Reverse Proxy

All services are proxied through Caddy for HTTPS with Let's Encrypt:
- Each service has a hostname env var (e.g., `N8N_HOSTNAME`, `FLOWISE_HOSTNAME`)
- No ports are exposed from services; Caddy handles all external traffic on ports 80/443
- Basic auth is optionally configured for sensitive services (Prometheus, SearXNG, RAGApp, etc.)
- Caddyfile uses env placeholders: `{$SERVICE_HOSTNAME}`, `{$SERVICE_USERNAME}`, `{$SERVICE_PASSWORD_HASH}`

### Environment Configuration

- `.env.example` - Template with all possible variables
- `.env` - Generated by `03_generate_secrets.sh`, persists across runs
- Secret generation types in `03_generate_secrets.sh`:
  - `password:32` - Alphanumeric password
  - `secret:64` - Base64-encoded secret
  - `hex:64` - Hexadecimal key
  - `fixed:value` - Fixed value
  - `langfuse_pk:32` / `langfuse_sk:32` - Special prefixed keys

## Common Development Tasks

### Running the Installer

```bash
# Full installation
sudo bash ./scripts/install.sh

# Update to latest versions
sudo bash ./scripts/update.sh

# Docker cleanup (free disk space)
sudo bash ./scripts/docker_cleanup.sh
```

### Managing Services

```bash
# Start all services
docker compose -p localai up -d

# Restart specific service
docker compose -p localai restart n8n

# View logs
docker compose -p localai logs -f n8n
docker compose -p localai logs -f --tail=200 caddy | cat

# Rebuild and recreate service
docker compose -p localai up -d --no-deps --force-recreate caddy

# Stop all services
docker compose -p localai down
```

### Regenerating Secrets

```bash
# Regenerate .env (preserves existing values)
sudo bash ./scripts/03_generate_secrets.sh
```

### Rerunning Service Wizard

```bash
sudo bash ./scripts/04_wizard.sh
```

## Adding a New Service

Follow the guide in `.cursor/rules/add-new-service.mdc`. Key steps:

1. **docker-compose.yml**: Add service with `profiles: ["myservice"]`, no `ports:` exposed
2. **Caddyfile**: Add reverse proxy block with `{$MYSERVICE_HOSTNAME}`
3. **.env.example**: Add hostname, optional credentials
4. **scripts/03_generate_secrets.sh**: Generate passwords and bcrypt hashes for Caddy basic auth
5. **scripts/04_wizard.sh**: Add to `base_services_data` array
6. **scripts/07_final_report.sh**: Add conditional output block with `is_profile_active "myservice"`
7. **README.md**: Add one-line description under "What's Included"

**Important**: Always ask whether the service needs Caddy basic auth. If yes, generate username/password/hash and add to Caddyfile.

## Important Conventions

### Logging

Use utility functions from `scripts/utils.sh`:
```bash
log_info "Information message"
log_success "Success message"
log_warning "Warning message"
log_error "Error message"
```

### Whiptail Dialogs

Use helpers from `scripts/utils.sh`:
```bash
require_whiptail  # Check if installed
wt_input "Title" "Prompt" "default"  # Input box
wt_password "Title" "Prompt"  # Password box
wt_yesno "Title" "Prompt" "yes|no"  # Yes/No dialog
wt_msg "Title" "Message"  # Message box
```

### Service Detection

In report scripts:
```bash
is_profile_active() {
    local profile_name="$1"
    [[ ",$COMPOSE_PROFILES," == *",$profile_name,"* ]]
}

if is_profile_active "myservice"; then
    # Print service info
fi
```

### n8n Worker Scaling

To change worker count: edit `N8N_WORKER_COUNT` in `.env`, then:
```bash
docker compose -p localai up -d --no-deps --scale n8n-worker=${N8N_WORKER_COUNT}
```

## Testing and Verification

After changes:

1. Regenerate secrets: `sudo bash ./scripts/03_generate_secrets.sh`
2. Restart affected services: `docker compose -p localai up -d --no-deps --force-recreate <service>`
3. Check logs: `docker compose -p localai logs -f <service> | cat`
4. Verify Caddy config: `docker compose -p localai exec caddy caddy validate --config /etc/caddy/Caddyfile`
5. Test external access: `curl -I https://<hostname>`

## Special Services

### Supabase
Complex multi-container setup with Kong, GoTrue, PostgREST, Realtime, Storage, etc. Configured in `scripts/05_configure_services.sh`.

### Langfuse
Requires Clickhouse, Minio (S3 storage), Postgres, Redis. Worker + Web containers.

### Dify
AI application platform with comprehensive LLMOps capabilities. Multi-container setup.

### RAGFlow
RAG (Retrieval-Augmented Generation) engine with deep document understanding. Configured via `docker-compose.override.yml`:
- **ragflow-mysql** - MySQL 8.0 database (port 3307)
- **ragflow-elasticsearch** - Document search engine (port 9201)
- **ragflow-minio** - S3-compatible object storage (ports 9000-9001)
- **ragflow-redis** - Caching layer (port 6380)
- **ragflow-server** - Main RAGFlow application with GPU support (port 9380)
- GPU support via NVIDIA Container Toolkit (configurable via `RAGFLOW_GPU_COUNT`)
- Nginx configuration mounted from `ragflow/nginx/ragflow.conf` for frontend/API routing
- Data directories: `ragflow/data/{mysql,elasticsearch,minio,redis,ragflow}`
- Environment: `ragflow/docker/.env` (excluded from git)

**Important**: RAGFlow uses nginx internally to serve frontend (`/ragflow/web/dist`) and proxy API requests to Flask (port 9380). The nginx configuration must be mounted as a volume to persist across container restarts.

### Python Runner
Internal-only service (no Caddy proxy) for running custom Python from `./python-runner/`. Entry point: `main.py`, dependencies: `requirements.txt`.
